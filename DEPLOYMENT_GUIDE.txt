================================================================================
           VPS DEPLOYMENT GUIDE - NEXT.JS APPLICATION
           Turab Root Website - Complete Step-by-Step Tutorial
================================================================================

WHY CODE WORKS FOR ME BUT NOT WHEN YOU DEPLOY:
===============================================

When you give me your code, it works perfectly because:

1. DEPENDENCIES ARE INSTALLED CORRECTLY
   - All npm packages are fetched and installed properly
   - Every library used (React, Next.js, Tailwind, etc.) is available
   - The build process can find and use all these dependencies

2. BUILD ARTIFACTS ARE GENERATED
   - The `.next` folder is created with compiled JavaScript
   - CSS from Tailwind is compiled and optimized
   - This folder is what actually runs in production, not the source code

3. ENVIRONMENT IS PROPERLY CONFIGURED
   - Node.js version is compatible
   - Environment variables are set correctly
   - The custom server (server.ts) can start without errors

4. SERVICE WORKER IS WORKING
   - The service worker (/public/sw.js) is served correctly
   - Browser can fetch and cache assets properly
   - Offline functionality works as designed

When you deploy to your VPS without these steps, the application breaks because:
- Dependencies might not be installed
- Build process might fail silently
- Service worker can't find assets to cache
- Wrong environment variables cause features to fail


OFFLINE FUNCTIONALITY EXPLANATION:
==================================

Your experience with offline functionality being "awful" likely happened because:

1. SERVICE WORKER WASN'T REGISTERED
   - The service worker file needs to be at /public/sw.js
   - Browser must be able to fetch it from the web server
   - If not registered, NO offline support exists

2. NOTHING WAS CACHED
   - First visit: Service worker tries to cache assets
   - If build is wrong, assets don't exist to cache
   - If web server doesn't serve /public/sw.js, registration fails
   - Result: Offline access shows "Check your connection" fallback

3. ASSETS WEREN'T BUNDLED
   - CSS, JavaScript, and images need to be in the build output
   - Without proper `npm run build`, these files don't exist
   - Service worker tries to cache missing files
   - Website appears broken or unstyled offline

HOW TO FIX: Follow this guide completely, especially steps 6-8 about building and
service worker verification.


================================================================================
PART 1: VPS SERVER SETUP (Linux - Ubuntu 20.04 or 22.04 recommended)
================================================================================

Step 1: SSH Into Your VPS
------------------------
From your computer, open terminal/command prompt and run:

ssh root@YOUR_VPS_IP_ADDRESS

When prompted, enter your VPS password. You'll see a terminal prompt like:
root@vps:~#

(Note: Replace YOUR_VPS_IP_ADDRESS with actual IP from your VPS provider)


Step 2: Update System Packages
------------------------------
Run these commands to ensure your system is up-to-date:

sudo apt update
sudo apt upgrade -y

This takes a few minutes. When complete, you'll see:
root@vps:~#


Step 3: Install Node.js (v18 or v20 recommended)
------------------------------------------------
Your app requires Node.js. Install it using NodeSource repository:

curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

Verify installation by checking versions:

node --version
npm --version

You should see output like:
v20.x.x
x.x.x


Step 4: Install PM2 (Process Manager)
-------------------------------------
PM2 keeps your app running even after terminal closes and restarts on server reboot:

sudo npm install -g pm2

Verify:
pm2 --version


Step 5: Install Nginx (Web Server & Reverse Proxy)
--------------------------------------------------
Nginx sits in front of your Node.js app:
- Serves static files quickly
- Handles SSL/HTTPS
- Manages incoming connections
- Provides good performance

sudo apt install -y nginx

Start Nginx:
sudo systemctl start nginx
sudo systemctl enable nginx

Check status:
sudo systemctl status nginx

You should see "active (running)"


Step 6: Install SQLite Development Files (if using SQLite database)
-------------------------------------------------------------------
Your app uses SQLite database by default. Install support:

sudo apt install -y sqlite3 libsqlite3-dev

(If you plan to use PostgreSQL instead, see ALTERNATIVE DATABASE SETUP section)


================================================================================
PART 2: PREPARE YOUR VPS FOR YOUR APPLICATION CODE
================================================================================

Step 7: Create Application Directory
------------------------------------
Create a folder where your app will live:

sudo mkdir -p /var/www/turab-root
cd /var/www/turab-root

Give yourself ownership:
sudo chown -R $USER:$USER /var/www/turab-root


Step 8: Transfer Your Code to VPS
----------------------------------
You have 3 options:

OPTION A: Using Git (RECOMMENDED if you use GitHub/GitLab)
---------
1. Push your code to a Git repository (GitHub, GitLab, or self-hosted)
2. On VPS, clone your repository:

cd /var/www/turab-root
git clone https://your-repo-url.git .
git config core.filemode false

3. Continue to Step 9


OPTION B: Using SCP (If you have code on your computer)
-------
From your local computer terminal (NOT VPS):

scp -r /path/to/your/project/* root@YOUR_VPS_IP:/var/www/turab-root/

Example:
scp -r ./turab-root-project/* root@123.45.67.89:/var/www/turab-root/


OPTION C: Using SFTP (If you prefer graphical interface)
-------
Use WinSCP (Windows), FileZilla (any OS), or Transmit (Mac):
- Host: YOUR_VPS_IP
- Username: root
- Password: your_vps_password
- Drag-drop your project files to /var/www/turab-root


Step 9: Verify Code Transfer
-----------------------------
List files to confirm your code is there:

ls -la /var/www/turab-root/

You should see: package.json, next.config.ts, server.ts, src/, public/, etc.


================================================================================
PART 3: INSTALL DEPENDENCIES AND BUILD APPLICATION
================================================================================

Step 10: Install NPM Dependencies
---------------------------------
This downloads all required packages (Next.js, React, Tailwind, etc.):

cd /var/www/turab-root
npm install

⚠️ IMPORTANT: This can take 5-15 minutes. Watch for:
- "added X packages" - Success
- "ERR!" - Error (see troubleshooting at end)

If you see errors:
npm install --legacy-peer-deps


Step 11: Create Environment File
--------------------------------
Your app needs a `.env.local` file with configuration:

cd /var/www/turab-root
cat > .env.local << 'EOF'
# Node environment
NODE_ENV=production

# Database (using SQLite)
DATABASE_URL="file:./prisma/dev.db"

# Port (keep as 3000 - Nginx will handle external access)
PORT=3000

# NextAuth Configuration (if you use authentication)
NEXTAUTH_SECRET="generate-a-random-secret-here"
NEXTAUTH_URL="https://yourdomain.com"

# Add any other environment variables your app needs here
EOF

To generate NEXTAUTH_SECRET, run:
openssl rand -base64 32

Then copy the output and replace "generate-a-random-secret-here" with it.


Step 12: Initialize Database (if using SQLite)
----------------------------------------------
Create database schema:

cd /var/www/turab-root
npx prisma db push

Choose "y" when asked to create database. You should see:
✔ Database synced to the schema

(If using PostgreSQL, adjust DATABASE_URL in step 11)


Step 13: Build Your Application
-------------------------------
This creates the `.next` folder with compiled, optimized code:

cd /var/www/turab-root
npm run build

Watch for: "✓ Compiled successfully"

⚠️ CRITICAL: Without this step, your service worker won't work offline and the
   app won't run. Your app is not ready without this folder.

When successful, you'll see:
✓ Compiled successfully
✓ Linting and checking validity of types
✓ Collecting page data
Route (pages)                              Size
┌ /                                         XXX kB
├ /about                                    XXX kB
├ /contact                                  XXX kB
├ /projects                                 XXX kB

This confirms the build succeeded and all pages compiled.

PART 4: START APPLICATION WITH PM2
================================================================================

Step 14: Start Application with PM2
-----------------------------------
PM2 will manage your Node.js process:

cd /var/www/turab-root
pm2 start npm --name "turab-root" -- start

You should see:

Wait a few seconds for startup. Check if it's running:

pm2 status

You should see:

│ id  │ name         │ namespace   │ mode │ pid      │ status   │
├─────┼──────────────┼─────────────┼──────┼──────────┼──────────┤

└─────┴──────────────┴─────────────┴──────┴──────────┴──────────┘

If status is not "online", check logs:

pm2 logs turab-root

Look for errors and check troubleshooting section below.


Step 15: Make PM2 Start on Server Reboot
-----------------------------------------
This ensures your app starts automatically when VPS restarts:

pm2 startup
pm2 save

When you run `pm2 startup`, you'll see instructions to copy/paste. Run them.
Then run:
pm2 save


================================================================================
PART 5: CONFIGURE NGINX AS REVERSE PROXY
================================================================================

Step 16: Create Nginx Configuration File
-----------------------------------------
Nginx will forward internet traffic to your Node.js app on port 3000:

sudo nano /etc/nginx/sites-available/turab-root

Paste this configuration (right-click in nano to paste):

server {
    listen 80;
    server_name YOUR_DOMAIN_HERE;

    # Redirect HTTP to HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name YOUR_DOMAIN_HERE;

    # SSL Certificate paths (we'll get these in next step)
    ssl_certificate /etc/letsencrypt/live/YOUR_DOMAIN_HERE/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/YOUR_DOMAIN_HERE/privkey.pem;

    # SSL Configuration
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;

    # Increase upload size limit
    client_max_body_size 50M;

    # Serve static files directly
    location ~* \.(jpg|jpeg|png|gif|ico|css|js|svg|woff|woff2|ttf|eot)$ {
        proxy_pass http://127.0.0.1:3000;
        proxy_cache_valid 200 10d;
        expires 10d;
        add_header Cache-Control "public, immutable";
    }

    # Proxy WebSocket connections (for Socket.IO)
    location /api/socketio {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Serve service worker with proper headers
    location /sw.js {
        proxy_pass http://127.0.0.1:3000;
        add_header Cache-Control "public, max-age=0, must-revalidate";
        add_header Service-Worker-Allowed "/";
    }

    # Proxy all other requests to Node.js app
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}

Replace "YOUR_DOMAIN_HERE" with your actual domain (e.g., turabroot.com)

To save and exit nano:
1. Press Ctrl+X
2. Press Y
3. Press Enter


Step 17: Enable Nginx Configuration
-----------------------------------
sudo ln -s /etc/nginx/sites-available/turab-root /etc/nginx/sites-enabled/

Test Nginx configuration:
sudo nginx -t

You should see:
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful


Step 18: Install SSL Certificate (HTTPS)
----------------------------------------
Use Let's Encrypt for free SSL certificate:

sudo apt install -y certbot python3-certbot-nginx

Run certbot (it will automatically update your Nginx config):
sudo certbot certonly --standalone -d YOUR_DOMAIN_HERE

Follow the prompts:
- Enter your email
- Agree to terms
- When asked about sharing email, choose your preference

Wait for "Successfully received certificate" message.

Restart Nginx:
sudo systemctl restart nginx

Test your domain in browser:
https://YOUR_DOMAIN_HERE

You should see your website! If you see Nginx welcome page, the config might need
adjustment (see troubleshooting).


Step 19: Auto-Renew SSL Certificate
-----------------------------------
Let's Encrypt certificates expire after 90 days. Set auto-renewal:

sudo certbot renew --dry-run

If successful, the renewal is already scheduled via cron.

================================================================================
TROUBLESHOOTING COMMON ISSUES
================================================================================

PROBLEM: "Command not found: node" or "node: not found"
SOLUTION: Node.js not installed. Go back to Step 3 and install it.

PROBLEM: npm install fails with error messages
SOLUTION: 
1. Clear npm cache: npm cache clean --force
2. Try: npm install --legacy-peer-deps
3. Check disk space: df -h (need at least 2GB free)

PROBLEM: npm run build fails
SOLUTION:
1. Check Node.js version: node --version (need v18+)
2. Make sure you're in right directory: pwd should show /var/www/turab-root
3. Check error messages carefully - usually tells you what's wrong
4. Try: npm install (again)

PROBLEM: "PM2 app is not running" or "status shows stopped"
SOLUTION:
1. Check logs: pm2 logs turab-root
2. Restart: pm2 restart turab-root
3. Make sure build succeeded: ls -la .next (should exist with folders inside)
4. Check port 3000 is not in use: lsof -i :3000

PROBLEM: "Cannot find module" errors in PM2 logs
SOLUTION:
1. npm install didn't work properly
2. Try: npm install --legacy-peer-deps
3. Make sure you're in: cd /var/www/turab-root

PROBLEM: Website shows "Bad Gateway" error
SOLUTION:
1. App is not running: pm2 status (check if online)
2. Wrong Nginx configuration: sudo nginx -t (check for errors)
3. Port 3000 is blocked: Ask VPS provider to unblock port 3000
4. Restart Nginx: sudo systemctl restart nginx

PROBLEM: SSL certificate error or "Not Secure"
SOLUTION:
1. Run Step 18 again to generate certificate
2. Wait 5 minutes for DNS to propagate
3. Check certificate: sudo certbot certificates
4. Restart Nginx: sudo systemctl restart nginx

PROBLEM: Service worker not registering / offline doesn't work
SOLUTION:
1. Check /sw.js is served: curl https://YOUR_DOMAIN_HERE/sw.js (should return JS code)
2. Check browser console (F12) for service worker errors
3. Make sure Nginx config has the /sw.js location block (Step 16)
4. Restart Nginx: sudo systemctl restart nginx
5. Clear browser cache: DevTools → Application → Clear Storage → Clear All

PROBLEM: Images not loading or styling looks broken
SOLUTION:
1. Ensure build succeeded: ls -la .next (should have size > 1MB)
2. Check Nginx is serving static files: curl https://YOUR_DOMAIN_HERE/_next/static/... 
3. Restart app: pm2 restart turab-root
4. Clear browser cache and hard refresh (Ctrl+Shift+R)

PROBLEM: App works fine, but performance is slow
SOLUTION:
1. Check server resources: top (then press 'q' to exit)
2. Check Node version: node --version (newer is faster)
3. Enable caching in Nginx: locations with ~* \.(jpg|css|js) cache for 10 days
4. Monitor logs for slowness: pm2 logs turab-root


QUICK EMERGENCY RESET:
If everything is broken and you want to start over:

pm2 delete turab-root
rm -rf /var/www/turab-root/*
# Now start from Step 8 again

Or to keep database but reset app:
pm2 restart turab-root
npm run build
pm2 restart turab-root


================================================================================
SECURITY CHECKLIST
================================================================================

After deployment, secure your server:

1. Change root password:
   passwd

2. Create non-root user (recommended):
   useradd -m -s /bin/bash appuser
   sudo usermod -aG sudo appuser

3. Set up firewall:
   sudo apt install -y ufw
   sudo ufw allow 22
   sudo ufw allow 80
   sudo ufw allow 443
   sudo ufw enable

4. Disable root login:
   sudo nano /etc/ssh/sshd_config
   Find "PermitRootLogin yes" and change to "no"
   Save and: sudo systemctl restart sshd

5. Keep system updated:
   sudo apt update && sudo apt upgrade -y

6. Monitor for problems:
   pm2 logs turab-root (regularly check)
